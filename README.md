# sherd-refit — автоматическая сборка 3D-сканов керамических фрагментов

## Что это и для чего

`sherd_refit` — консольная программа, которая берёт папку со сканами фрагментов одного разбитого
керамического предмета и подбирает наиболее вероятную сборку: сопоставляет фрагменты по
поверхностям излома и выдаёт для каждого жёсткое преобразование (поворот + перенос).
Работает только на процессоре, без видеокарты и без графического интерфейса, на macOS и Linux.
Вход — папка с файлами PLY/OBJ/STL (также читается OFF); выход — матрицы преобразований,
меши в найденных позициях, склеенная модель для каждой собранной группы, картинки-превью и
отчёт `report.md`, где по каждому стыку видно, почему он принят или отклонён.

## Установка

Нужен Python 3.10–3.12 (верхняя граница из-за готовых сборок open3d).

```bash
uv venv --python 3.12 .venv && source .venv/bin/activate && uv pip install -e .
```

Без `uv`:

```bash
python3.12 -m venv .venv && source .venv/bin/activate && pip install -e .
```

Ставятся numpy, scipy, open3d, pillow и сама команда `sherd_refit`.

Требования к данным:

- Меши должны быть замкнутыми или почти замкнутыми. Из каждого файла берётся наибольшая
  связная компонента; если после этого меш всё равно не замкнут, для него отключается проверка
  на взаимное проникновение, и в отчёте это отмечено (`watertight = False`).
- Все фрагменты в одних и тех же единицах и примерно одного масштаба. Толщина стенки `t`
  считается для каждого фрагмента отдельно, и пара сопоставляется по своей толщине, поэтому
  коллекция из горшков с разной стенкой — нормальный вход. Медиана по коллекции остаётся только
  для отчёта: фрагмент, у которого толщина отличается от неё больше чем на 40 %, помечается
  пометкой **(differs)**.
- Поперёк стенки должно укладываться хотя бы 4–5 рёбер меша. Меньше — и излом не разрешается
  сеткой; в отчёте это видно в столбце `edges per t`.
- В папке должно быть не меньше двух файлов.
- Цвет не обязателен. При сопоставлении он не используется, но переносится в выходные меши.

## Быстрый старт

```bash
sherd-refit run input/test_fragments_1/fragments --out output/test_fragments_1
```

В папке `--out` появляется:

| файл | что это |
|---|---|
| `report.md` | отчёт для чтения человеком: фрагменты, группы, принятые стыки и их оценки |
| `report.json` | то же самое в машинном виде плюс все кандидаты по каждой паре |
| `transforms.json` | матрица 4x4 на фрагмент, номер группы, флаг `placed`, толщина стенки, параметры запуска |
| `placed/<имя>.ply` | исходный меш в полном разрешении, уже сдвинутый в найденную позицию |
| `assembly_<k>.ply` | один склеенный меш на каждую группу из двух и более фрагментов |
| `preview_<k>.png` | четыре вида собранной группы, каждый фрагмент своим цветом (подпись сверху) |
| `preview_segmentation.png` | все фрагменты в ряд, красным — распознанная поверхность излома |
| `cache/<имя>.npz` | результат предобработки одного фрагмента, чтобы повторный запуск не считал заново |

Смотреть результат: `assembly_0.ply` и файлы из `placed/` открываются любым просмотрщиком
мешей — MeshLab, Blender, CloudCompare. Просмотрщик macOS Preview для PLY ненадёжен, цвета
вершин он показывает не всегда, поэтому проверять сборку лучше в MeshLab или Blender.
Для быстрой оценки достаточно PNG-превью: цвета там служебные (серый, оранжевый, синий и т. д.),
это не цвет самой керамики.

### Как читать таблицу стыков в report.md

Все расстояния выражены в толщинах стенки `t` (на тестовом наборе `t` = 38.9 единиц),
поэтому пороги не зависят от масштаба сканов.

**Толщина стенки и разрешение сетки.** Каждый порог расстояния задан сразу в двух единицах и
равен `max(k·t, m·res)`. Первое слагаемое, `k·t`, делает пайплайн независимым от масштаба скана.
Второе, `m·res`, где `res` — медианная длина ребра рабочего меша, не даёт требовать точности,
которой в сетке нет: `m` — это счёт рёбер. На толстостенной терракоте из `test_fragments_1`
поперёк стенки укладывается 17 рёбер (`res` = 0.058 `t`), и там во всех порогах побеждает первое
слагаемое — множители подобраны именно так, чтобы на этом наборе ничего не изменилось. На
тонкостенном горшке поперёк стенки бывает 4–6 рёбер, и включается второе: например, порог
плотного прилегания `0.01 t` там равен 0.035 мм, то есть много меньше одного треугольника.

Для пары фрагментов `t` = меньшая из двух толщин (венчик и утолщённый край завышают оценку,
стенка — это меньшее из двух), а `res` = большая из двух: точность пары ограничивает более грубая
сетка. В таблицах отчёта у каждого кандидата выписаны обе величины, по которым его судили:
`tight at (t)` и `gap limit (t)`.

| столбец | что означает | как читать |
|---|---|---|
| `score` | `seam` × `tight`, только для сортировки | больше — надёжнее |
| `seam (t)` | длина общего шва вдоль линии излома, в толщинах стенки | принимается от 3; настоящие стыки на тестовом наборе дают 11 и 21 |
| `tight A/B` | доля точек излома, прилегающих к поверхности излома соседа плотнее чем `tight at`, отдельно для каждого фрагмента | решение принимается по меньшему из двух; порог 0.25 |
| `tight at (t)` | на каком расстоянии для этой пары считалось прилегание | `max(0.01 t, 0.15 res)` |
| `gap (t)` | медианный зазор между обращёнными друг к другу поверхностями излома | сравнивается со столбцом `gap limit` |
| `gap limit (t)` | предел зазора для этой пары | `max(0.03 t, 0.45 res)` |
| `contact (t²)` | площадь фактического контакта в квадратах толщины | в порогах не участвует, показывает, насколько крупный стык |
| `shell cont.` | средняя высота уступа внешней поверхности поперёк шва, в `t` | меньше — глаже переход; в порогах не участвует |
| `normal agr.` | согласованность нормалей внешней поверхности по обе стороны шва | 1.0 — поверхность продолжается гладко, порог 0.8 |
| `penetration` | доля точек поверхности, ушедших внутрь соседа глубже 0.06 t | порог 0.005; 0.0000 означает, что фрагменты не пересекаются |

Если включён `--early-reject-tight` (по умолчанию выключен) и у кандидата в столбце
`normal agr.` стоит `-1.00`, а `penetration` равен нулю, значит он был отсеян рано: плотность
прилегания оказалась настолько мала, что считать проникновение и непрерывность уже не имело
смысла. В `report.json` у такого кандидата стоит `partial = 1`.

Кроме принятых стыков в отчёте есть раздел **Best candidate per pair** — лучший кандидат по
каждой паре фрагментов, включая отклонённые. По нему видно, насколько ложные варианты
отстают от настоящих. Раздел **Accepted joins not used** перечисляет стыки, прошедшие пороги,
но отвергнутые при сборке (например, из-за проникновения в уже поставленный фрагмент).

## Как это работает

1. **Предобработка.** Меш прореживается до 200 000 граней (рабочая копия; оригинал сохраняется
   для вывода и финальной доводки) и слегка сглаживается. Толщина стенки `t` оценивается лучами,
   пущенными внутрь от случайных граней: берётся самое частое расстояние до противоположной
   стенки. Все пороги дальше выражены в `t`, поэтому пайплайн не зависит от масштаба.
2. **Разделение на внешнюю поверхность и излом.** Из каждой грани внутрь пускается конус из семи
   лучей. Если они попадают в противоположную стенку на расстоянии 0.5–1.8 `t` и с изнанки,
   грань относится к целой поверхности. Всё остальное — излом. Затем результат чистится
   фильтром большинства, мелкие островки убираются, а граница уточняется.
3. **Линии излома (breaklines).** Рёбра между целой гранью и гранью излома дают линию слома.
   В каждой её точке строится локальный репер из усреднённой нормали внешней поверхности и
   нормали излома. Двугранный угол между ними обычно 40–100°.
   Обе нормали усредняются **не по всей окрестности точки, а по кольцу** от `0.15 t` до `0.60 t`
   (поля `macro_inner` и `macro_outer` в `Params`, флага командной строки у них нет). Причина в самом ребре
   слома: на реальных черепках оно окатано, а рабочий меш ещё и сглажен, поэтому грани у самой
   линии заваливаются друг к другу и тянут обе макронормали навстречу. Замерено на парах
   фрагментов, поставленных в эталонные позиции: сумма двугранных углов настоящей пары
   получалась 142° вместо 180°, то есть верные пары рамок лежали на самом краю допуска и
   примерно половина их отбрасывалась ещё до оценки. С кольцом сумма равна 179 ± 4°.
4. **Гипотезы позиций.** Каждая пара точек линии излома (одна на фрагменте A, одна на B) с
   дополняющими друг друга двугранными углами задаёт одно жёсткое преобразование. Таких гипотез
   на пару десятки тысяч; они быстро отсеиваются по тому, сколько точек линии слома B легло на
   линию слома A.
5. **Многоступенчатый ICP.** Выжившие гипотезы уточняются: сначала ICP по линиям излома, затем
   по точкам излома вместе с приграничной полосой внешней поверхности, затем только по излому,
   со всё меньшим радиусом поиска. Кандидаты одной пары считаются в несколько потоков.
6. **Проверка.** Каждый кандидат проверяется по плотности прилегания, зазору, длине шва,
   непрерывности внешней поверхности и отсутствию взаимного проникновения. Стык принимается,
   только если пройдены все пять порогов.
7. **Глобальная сборка.** Принятые стыки сортируются по надёжности. Группа наращивается жадно:
   каждый новый фрагмент проверяется на проникновение во все уже поставленные, а если он связан
   с группой несколькими стыками, они должны давать согласованную позицию (расхождение не больше
   10° и 0.5 `t`). Когда группу нарастить нечем, начинается новая. Фрагменты без принятых стыков
   остаются несобранными: инструмент никогда не приставляет их силой.
8. **Доводка на полном разрешении.** Для каждого принятого стыка ICP повторяется на вершинах
   излома исходных, непрореженных мешей, что снимает погрешность прореживания и сглаживания.

Метод относится к семейству сопоставления по поверхностям излома (Huang et al., 2006), где
линии слома работают дешёвым генератором позиций. Подход Structure-from-Sherds, опирающийся на
ось вращения сосуда, для первого тестового набора не годится: предмет не является телом
вращения, оценка оси бессмысленна, и сборка получалась неверной.

## Параметры CLI

```
sherd-refit run INPUT_DIR --out OUT_DIR [опции]
sherd-refit segment INPUT_DIR --out OUT_DIR [--target-faces N] [--workers N] [-v]
```

| флаг | по умолчанию | когда менять |
|---|---|---|
| `--out` | обязателен | папка для результатов; в неё же кладётся кэш |
| `--target-faces` | `200000` | верхний предел граней рабочего меша. Фактический бюджет выбирается автоматически: ~600 граней на t² площади (около 12 рёбер на толщину стенки), но не меньше 50000 и не больше этого предела. Для тонкостенной керамики с большими фрагментами поднимайте предел (300000–400000) |
| `--workers` | число ядер минус 1 | уменьшайте при нехватке памяти: каждый процесс держит два фрагмента целиком |
| `--threads` | число ядер, делённое на число процессов | сколько потоков внутри одного процесса сопоставления. Потоки считают кандидатов одной пары параллельно; по умолчанию процессы × потоки ≈ число ядер. Ставьте 1, если хотите ровно один поток на пару |
| `--candidates` | `10` | сколько кандидатов на пару доводится полным ICP. Это главная статья расходов пары. Измерено на горшках A, B, C, H и `synthetic_pingsdorf_20`: верная поза после первой стадии оказывается на месте 0 в медиане и не ниже 6-го на всех наборах, поэтому 10 хватает с запасом (прежнее значение 40 стоило вчетверо дороже и ничего не добавляло). Поднимайте до 20–40 на трудных наборах, время растёт линейно |
| `--stage1` | `250` | сколько гипотез доводится по линиям излома. Верная поза в грубом ранжировании лежит не ниже 150-го места в 78–92 % случаев; поднимать вместе с `--candidates` |
| `--brk-voxel` | `0.5` | в толщинах стенки: воксель, до которого прореживается линия излома перед подбором пар рамок. Число гипотез растёт как обратный квадрат этой величины. При 1/3 (прежнее значение) на горшке A выходит 390 тысяч гипотез на пару и 10.2 c процессорного времени, при 0.5 — 177 тысяч и 5.6 c, и ни одного потерянного стыка |
| `--dihedral-tol` | `25` | в градусах: допуск на \|dih_A + dih_B − 180\| при отборе пар рамок. После починки макронормалей (см. ниже) сумма двусторонних углов настоящей пары лежит на 179 ± 4 градусах, и 25 градусов оставляют 97.6 % совпадающих точек против 40 градусов прежде |
| `--min-tight` | `0.25` | минимальная доля плотного прилегания; снизьте до 0.20 для сработанных, окатанных краёв излома |
| `--max-gap` | `0.03` | множитель `k` для максимального зазора; фактический предел пары — `max(0.03 t, 0.45 res)`. Повышайте, если известно, что края обиты |
| `--thick-ratio` | `2.5` | пара, у которой толщины стенок различаются больше чем в это число раз, не сопоставляется вовсе. Это только отсев; прежнее значение 1.5 отбрасывало настоящие стыки с венчиком (на горшках A и B — по 6 пар из 15) |
| `--screen-top-k` | `0` (выключено) | предварительный отбор партнёров: сколько кандидатов на фрагмент оставить перед сопоставлением. Отбор — это дешёвая (0.17 c процессорного времени на пару) грубая стадия по линиям излома на прореженной выборке; на коллекции из 164 фрагментов он сокращает 12 589 пар до 1 950 при K = 15 и режет время сопоставления в разы. **Он теряет настоящие стыки, и потому выключен по умолчанию:** на `mixed_all` при K = 15 остаётся 47 % соседних пар из эталона, при K = 30 — 64 %, на синтетическом наборе из 170 фрагментов ещё меньше. Включайте на коллекциях, где полный перебор не укладывается во время; числа и объяснение, почему дешёвый отбор на этих данных не работает лучше, — в `docs/superpowers/notes/2026-09-06-scale-pairs.md` |
| `--screen-points` | `150` | сколько точек линии излома берётся на фрагмент при отборе. Стоимость растёт как квадрат этого числа; 350 точек стоят втрое дороже и не меняют результат отбора |
| `--screen-min-pairs` | `200` | ниже этого числа пар отбор не запускается вовсе, даже если `--screen-top-k` задан. Все эталонные наборы (терракота, горшки A–J, `synthetic_pingsdorf_20`) остаются ниже порога |
| `--max-pen` | `0.005` | допустимая доля проникновения; ослаблять почти никогда не нужно |
| `--min-seam` | `3.0` | минимальная длина шва в `t`; снизьте, если фрагменты мелкие и стыки короткие |
| `--stage1-floor` | `0` (выключено) | если лучшая оценка пары по линиям излома после первой стадии ниже этого порога, вторая стадия для неё не запускается вовсе: пара сохраняет свою позу, помечается в отчёте как `partial` и никогда не принимается. Механизм точный и бесплатный, когда выключен, но **безопасного порога на этих данных нет**: у соседних пар медиана оценки 0.21–0.25, у остальных 0.19–0.22, и порог, отсекающий половину пар, стоит 10–40 % настоящих соседей. Числа в `docs/superpowers/notes/2026-09-06-scale-pairs.md` |
| `--second-pass-top` | `0` (выключено) | сколько лучших партнёров каждого несобранного фрагмента пересчитать вторым проходом с увеличенным бюджетом (`--second-pass-stage1`, `--second-pass-candidates`). Первый проход намеренно дешёвый; второй тратит освободившееся время только там, где сборка ничего не нашла |
| `--second-pass-stage1` | `400` | сколько гипотез доводится во втором проходе |
| `--second-pass-candidates` | `40` | сколько кандидатов доводится полным ICP во втором проходе |
| `--early-reject-tight` | `0` (выключено) | если больше нуля, кандидаты с плотностью прилегания ниже этого значения (замер сразу после ICP по излому с приграничной полосой) дальше не доводятся: пропускаются два последних ICP, проверка проникновения и непрерывности. Такой кандидат помечен в `report.json` как `partial = 1`, у него `penetration = 0` и `normal agr. = -1` (не считались), и он никогда не принимается. **Выключено по умолчанию:** на тестовом наборе плотность прилегания успевает вырасти ещё на 0.09 за оставшиеся два ICP, поэтому безопасный порог экономит около 7 % времени сопоставления. Включайте (0.10 и не выше), только если готовы к этому размену |
| `--margin-points` | `6000` | сколько точек приграничной полосы внешней поверхности берётся на фрагмент для ICP и проверки непрерывности. Это главный источник ускорения: полоса — это 13 000 из 30 000 точек, и именно она определяет стоимость ICP. На тестовом наборе оценки настоящих стыков меняются меньше, чем от смены зерна выборки. `0` — не прореживать вовсе |
| `--surface-points` | `20000` | сколько точек берётся по всей поверхности фрагмента. На них считается проникновение и из них выделяется приграничная полоса |
| `--frac-density` | `150` | сколько точек берётся на каждый `t²` площади излома (не меньше 5000 и не больше 12000 на фрагмент). Плотность задана в `t²`, а не числом на фрагмент, чтобы крупный черепок описывался так же подробно, как мелкий. На сами оценки число точек почти не влияет — оно кормит ICP: на 50 точках вместо 150 горшок A собирается на 5 фрагментов из 8 вместо 7. Верхняя граница держит стоимость ICP в узде |
| `--no-preview` | выкл. | не рисовать PNG, экономит время на больших наборах |
| `--no-refine` | выкл. | пропустить доводку на полном разрешении |
| `--no-meshes` | выкл. | не писать меши, только отчёт и матрицы; удобно для быстрой проверки параметров |
| `-v`, `--verbose` | выкл. | подробный лог по каждой паре |

Подкоманда `sherd-refit segment` выполняет только предобработку и сегментацию: пишет кэш и
`preview_segmentation.png`, ничего не сопоставляя. Это самый быстрый способ проверить, что
излом распознан правильно.

Кэш в `<out>/cache` хранит бюджет граней, версию формата и дату файла скана; при изменении
любого из них фрагмент пересчитывается автоматически. Удалять папку вручную не нужно.

## Результат на тестовом наборе test_fragments_1

Четыре фрагмента, толщина стенки 38.6 единиц. Инструмент собирает три из них в одну группу —
FY234104 – FY234094 – FY234021 в ряд, 094 посередине — и оставляет FY234007 несобранным.
Это совпадает с ручной сборкой музея: три части из четырёх.

Оценки принятых стыков:

| стык | seam (t) | tight A/B | gap (t) | penetration |
|---|---|---|---|---|
| 021 – 094 | 21.3 | 0.27 / 0.41 | 0.060 | 0.0000 |
| 094 – 104 | 11.3 | 0.42 / 0.28 | 0.057 | 0.0000 |

Ложные кандидаты отстают с запасом: у лучшего из них плотность прилегания не выше 0.19 хотя бы
с одной стороны, а зазор не меньше 0.076 `t`. Ни один из них не проходит пороги.

Время работы примерно полторы минуты на MacBook с M2 Pro. По таблице Timing в отчёте:
предобработка 17 с, попарное сопоставление 48 с, сборка 1 с, доводка 9 с; запись мешей и
рисование превью в таблицу не попадают. Как получены эти числа, что было медленным раньше и
какие ускорения пришлось отклонить ради качества сборки —
в `docs/superpowers/notes/2026-09-05-performance.md`.

## Ограничения и что делать, если не собралось

- **Сначала откройте `preview_segmentation.png`.** Красным показана распознанная поверхность
  излома. Если излом не красный или красным залито пол-фрагмента, сегментация не удалась, и
  ничего дальше по цепочке работать не может. Проверять сегментацию отдельно:
  `sherd-refit segment INPUT_DIR --out OUT_DIR`.
- **Сработанные, окатанные или обитые края излома** снижают плотность прилегания. Если в таблице
  Best candidate per pair видна пара с длинным швом и правдоподобной геометрией, но `tight` около
  0.2, попробуйте `--min-tight 0.2`, при необходимости вместе с `--max-gap 0.08`.
- **Тонкие фрагменты.** Если поперёк стенки укладывается меньше 15 рёбер, пороги переходят на
  второе слагаемое формулы `max(k·t, m·res)` и становятся мягче: это не настройка, а признание
  того, что более точного ответа в сетке нет. Что происходит, видно по столбцам `edges per t`,
  `tight at` и `gap limit` в `report.md`. Если рёбер меньше четырёх, излом не разрешается сеткой
  вовсе, и помочь может только более подробный скан: `--target-faces` тут бесполезен, он лишь
  ограничивает прореживание сверху.
- **Фрагменты от разных предметов**, попавшие в одну папку, остаются несобранными или образуют
  отдельные группы. Это нормальный исход, а не ошибка.
- **Инструмент никогда не собирает через силу.** Если ни один стык не прошёл пороги, в отчёте
  будет строка «not assembled (no confident join)», и все фрагменты останутся на месте.
- **Незамкнутые меши** лишаются проверки на проникновение: для них признак `watertight` в отчёте
  равен `False`, и ложный стык отсеять сложнее.
- **Трудный набор.** Поднимите `--candidates` и `--stage1`, это увеличивает шанс, что верная
  позиция доживёт до проверки, ценой пропорционального роста времени.

## Разработка

Состав пакета:

- `sherd_refit/cli.py` — разбор аргументов, подкоманды `run` и `segment`.
- `sherd_refit/pipeline.py` — порядок стадий, пулы процессов и распределение потоков, кэш,
  отрисовка превью.
- `sherd_refit/fragment.py` — загрузка, прореживание, оценка толщины, сегментация, линии излома
  (классы `Fragment` и `MatchData`).
- `sherd_refit/geometry.py` — мелкие геометрические утилиты: нормали граней, смежность,
  окрестности, выборка точек по поверхности.
- `sherd_refit/matching.py` — гипотезы, ICP, проверка кандидатов; класс `Params` собирает все
  пороги в одном месте.
- `sherd_refit/assembly.py` — жадная глобальная сборка с проверками проникновения и
  согласованности.
- `sherd_refit/refine.py` — доводка стыков на полном разрешении.
- `sherd_refit/render.py` — программный рендер точек в PNG без GPU и без дисплея.
- `sherd_refit/report.py` — запись `transforms.json`, `report.md`, `report.json` и мешей.

Тесты: `uv pip install -e ".[dev]"`, затем `pytest -q` (около двух минут, 30 тестов).
`tests/test_geometry.py` — модульные тесты геометрических функций; `tests/test_synthetic.py` —
синтетическая плита, разрезанная по бугристому излому с известным преобразованием: проверяются
сегментация, сопоставление (ошибка позы < 2° и < 0.1 t), сборка и весь конвейер;
`tests/test_integration_real.py` — прогон на `input/test_fragments_1` (папка ищется относительно
корня репозитория) с проверкой, что приняты ровно стыки 021–094 и 094–104. Долгие тесты помечены маркером `slow`: `pytest -q -m "not slow"` идёт
около минуты.

Документация: `docs/superpowers/specs/2026-09-05-fracture-reassembly-design.md` — проектное
решение с измеренными характеристиками данных и обоснованием порогов;
`docs/superpowers/notes/2026-09-05-papers-*.md` — разбор литературы, на котором построен выбор
метода; `papers/` — сами статьи.
