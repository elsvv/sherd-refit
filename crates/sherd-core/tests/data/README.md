# IO test data (plan step S2)

Everything here is generated by `tools/make_io_expectations.py` (run it from the repository root
with the venv active). Nothing is hand-edited, and `io_expected.json` holds the numbers the Rust
tests assert against — all of them produced by Open3D 0.19, the reference reader.

| file | what it pins down |
|---|---|
| `tetra_binary_le.ply` | Open3D's own output layout: `double` xyz, `uchar` rgb, `list uchar uint`. The writer has to reproduce this file byte for byte |
| `tetra_binary_le_plain.ply` | the same without colours — the other header the writer emits |
| `tetra_ascii_crlf.ply` | ASCII, CRLF line ends, a mid-header comment, `float` coordinates, an `alpha` column to skip, `list uchar int` |
| `tetra_binary_be.ply` | binary **big**-endian, `float` coordinates, no colours |
| `polygons_ascii.ply` | a triangle, a quad and a pentagon under the name `vertex_index`, with `nx ny nz` to skip; the fan triangulation and the largest-component tie-break (two components of three faces each) |
| `messy_ascii.ply` | every cleaning pass at once: a duplicated vertex, the degenerate face it creates, an unreferenced vertex, and a second component |
| `tetra.obj` | `v x y z r g b` colours in `[0, 1]`, `f v/vt/vn` references, a `mtllib` that does not exist |
| `tetra_binary.stl`, `tetra_ascii.stl` | both STL encodings (Open3D cannot *write* ASCII STL, so that one is hand-built) |
| `tetra_coff.off` | Open3D's own OFF output: `COFF` with four integer colour columns |
| `quad_comment.off` | a `#` comment, a blank line and a quad to fan-triangulate |
| `tetra_color_u8.glb`, `tetra_color_f32.glb` | `COLOR_0` as normalised `u8` and as `f32`, under a node transform that must be applied |

`io_expected.json` also carries the same three stages for the benchmark files under `input/`,
which are never committed: a checkout without them skips those rows and still runs green.
